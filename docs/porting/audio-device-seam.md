# The audio device seam

`Core/Libraries/Source/OpenALAudioDevice` was a library nobody linked: it was built only by a
standalone CMake harness under `scripts/ci/openal-standalone`, which existed because
`.github/workflows/native-port-ci.yml` said the backend "is not reachable from the top-level CMake
build". This slice makes the real top-level build produce it and makes the engine's audio consumer
library compile against it at 64-bit, deletes the harness, and measures how much of the Miles API
surface the backend actually covers.

Nothing links a game binary and no sound has been played. The honest bar here is "the real build
compiles it, the symbol set matches, and N of the 19 consumer translation units compile at 64-bit".

## 1. The surface, re-measured

`scripts/audio-surface-scan.py` (new) is the measurement. It scans `WWAudio` and
`GameEngineDevice` (excluding `*/Tools/*` and the backend itself), counts `AIL_*` references two
ways — over the raw file text and over text with comments and string literals stripped — and then
reads the backend to classify what it does with each one.

| Measure | Code | Raw text | `audio-surface.md` said |
|---|---:|---:|---:|
| distinct `AIL_*` identifiers | 105 | **114** | 114 |
| ... functions | 94 | | 101 |
| ... constants / macros | 11 | | 13 |
| reference sites | 217 | **232** | 230 |
| files referencing Miles | 10 | 10 | 10 |

The original 114 and 10 reproduce exactly. Two numbers in `audio-surface.md` were slightly off and
are corrected there:

- **230 sites → 232.** Its own per-file table sums to 230 only because `WWAudio/Utils.h` is listed
  as 2 when the file contains 4 (two of them in a comment). Every other per-file count matches to
  the digit.
- **101 functions / 13 constants → 94 / 11 as seen by the compiler.** The 9 identifiers in the
  difference (`AIL_set_sample_volume`, `AIL_sample_pan`, `AIL_open_stream_by_sample`,
  `AIL_set_stream_volume`, …) occur *only* inside `// TheSuperHackers @fix xezon 05/04/2025
  Upgrades miles call from legacy …` comments. They are names of Miles entry points the engine
  stopped calling; a replacement library does not have to provide them.

The code-only column is the one that matters for linking, so the coverage table below is over the
94 functions. The raw column is kept because it is what the earlier measurement used, and because
having both is what made the discrepancy visible.

## 2. Coverage: what the OpenAL backend does with each of the 94

Classification is mechanical, from the backend's own sources: the scanner parses each `AIL_*`
definition, walks the backend's internal call graph, and asks whether the function transitively
reaches an `al*`/`alc*` call.

| Category | Count | Meaning |
|---|---:|---|
| implemented | 50 | reaches OpenAL |
| recorded | 35 | reads or writes backend state only, no OpenAL call |
| no-op | 6 | body is empty or only discards its arguments |
| alias | 3 | `#define` in `mss.h` onto another entry point |
| **missing** | **0** | demanded by the engine, absent from the backend |
| entry points defined by the backend | 101 | |
| prototypes declared by `mss/mss.h` | 101 | equal, checked by `scripts/ci/check-openal-symbols.py` |
| defined but never referenced by the engine | 10 | |

`recorded` is a machine-checkable property, not a verdict. Reading the 35 by hand, they fall into
two very different groups:

- **Complete without touching OpenAL** — `AIL_lock`/`AIL_unlock` (a real `std::recursive_mutex`),
  `AIL_mem_free_lock` (a real `free`), the `*_user_data` getters/setters, the EOS/stream callback
  registrations (the backend's service thread dispatches them), the provider/filter enumerators,
  `AIL_last_error`, and the position/length/loop-count queries that answer from state the
  implemented setters maintain.
- **Deliberate approximations or inert by design** — `AIL_set_filter_sample_preference` and
  `AIL_set_sample_processor` (reverb/mono-delay recorded, never audible: OpenAL Soft EFX is the
  route), `AIL_set_3D_speaker_type` (recorded so queries stay consistent; OpenAL Soft picks its own
  output config), `AIL_set_3D_sample_effects_level`, `AIL_get_DirectSound_info` (returns nulls),
  `AIL_waveOutClose` (flips the driver's open flag; device teardown happens in `AIL_shutdown`),
  `AIL_enumerate_filters`/`AIL_enumerate_3D_providers` (one synthetic provider each).

The 6 no-ops are `AIL_close_3D_provider`, `AIL_set_preference` (only `AIL_LOCK_PROTECTION` and
`DIG_USE_WAVEOUT` are ever set), `AIL_set_stream_loop_block`, and the three timer entry points
`AIL_get_timer_highest_delay`, `AIL_release_timer_handle`, `AIL_stop_timer` — the engine's only
Miles timer drove WWAudio's periodic update, which WWAudio now drives itself.

The full per-function table (94 rows, with call-site counts) is regenerated by
`python3 scripts/audio-surface-scan.py --markdown -`. `--check` exits non-zero if any demanded
function is missing, and CI runs it.

## 3. The seam

There is no new abstraction layer and not one of the 217 call sites changed. The build already had
the seam; it was only missing a consumer-visible wiring on the non-Windows branch:

```cmake
# CMakeLists.txt
if((WIN32 OR "${CMAKE_SYSTEM}" MATCHES "Windows") AND ${CMAKE_SIZEOF_VOID_P} EQUAL 4)
    include(cmake/miles.cmake)     # retail mss32.lib, unchanged
    ...
else()
    include(cmake/openal.cmake)    # supplies `milesstub` from the OpenAL backend
endif()
```

Every audio consumer links the `milesstub` interface target and includes `mss.h` by that name, so
substituting the implementation of that one target is the whole selection mechanism:

```cmake
# cmake/openal.cmake
add_subdirectory(Core/Libraries/Source/OpenALAudioDevice)
add_library(milesstub INTERFACE)
target_link_libraries(milesstub INTERFACE core_openalaudiodevice)
```

Changes made here: `cmake/openal.cmake` synthesises the `OpenAL::OpenAL` imported target when an
older CMake's `FindOpenAL` locates the library but not the target (it only defines the target from
3.27), and falls back to fetching `openal-soft` 1.23.1 when there is no system OpenAL;
`Core/Libraries/Source/OpenALAudioDevice/CMakeLists.txt` moves the `-Wall -Wextra` that used to
live in the standalone harness onto the real target. **32-bit Windows takes the `if` branch and is
untouched** — same `mss32.lib`, same headers, same call sites.

### What was deliberately not abstracted

- **No audio-device interface class.** The Miles C API *is* the interface, `mss.h` is its header,
  and `milesstub` is its build-system socket. Introducing a C++ device interface would have meant
  rewriting 217 call sites for no additional capability.
- **No CMake option to pick the backend.** The selection is platform/pointer-width, matching the
  existing `miles.cmake`/`bink.cmake`/`dx8.cmake` policy. A 64-bit Windows build gets OpenAL for
  the same reason it cannot get Miles: `mss32.lib` is 32-bit only.
- **`MilesAudioManager.cpp` is left alone.** It holds 100 of the 217 code references, and it does
  not compile natively yet — but not for audio reasons: it needs `windows.h`/`dinput.h` through
  `GameEngineDevice`, which is the PreRTS/Win32 slice, not this one. `Core/GameEngineDevice` sits
  at 6/70 native TUs before and after this change.

## 4. What had to change in the consumers, and why

Only what the compiler demanded, all of it `#ifdef _WIN32`-guarded so the Windows path is the
original code:

| File | Change |
|---|---|
| `WWAudio/Threads.{h,cpp}` | the delayed-release thread used `_beginthread` + `CreateEvent` + `WaitForSingleObject`. Off Windows it uses `WWPlatform::Thread_Create` and `WWPlatform::EventClass` (from `WWLib/platform/`, reused, not extended). `HANDLE`/`DWORD` in the signatures became `ThreadTokenType`/`TimeType`, which are `HANDLE`/`DWORD` on Windows. |
| `WWAudio/WWAudio.{h,cpp}` | Windows-only `HANDLE` overloads and file-mapping paths guarded; `lstrcmpi` → `stricmp`. |
| `WWAudio/SoundBuffer.{h,cpp}`, `WWAudio/Utils.h` | Win32 file mapping guarded; `LPCTSTR` helper parameters → `const char *`. |
| `WWAudio/SoundSceneObj.h`, `WWAudio/SoundScene.cpp` | `On_Event`'s two `uint32` payload parameters carry `SoundSceneObj *` pointers. Widened to `uintptr_t` (via `Utility/stdint_adapter.h`, since VC6 has no `<stdint.h>`), which is `unsigned int` on 32-bit Windows — same layout, same vtable. |
| `Dependencies/Utility/Utility/compat.h` | `TRUE`/`FALSE` fallbacks off Windows. |
| `WWMath/{vector3,matrix3,matrix3d}.h`, `WWSaveLoad/{pointerremap.h,definitionfactorymgr.cpp}` | removed five `#ifdef _UNIX #include "osdep.h"` blocks. The header does not exist anywhere in the repo, so these were dead on Windows and a hard error natively — the real build defines `_UNIX`. |

Since a `Thread_Create` handle cannot be waited on portably, the non-Windows shutdown path signals
a second event from the end of the thread body and waits on that, with the same timeout semantics.

## 5. Numbers

`scripts/native-port-probe.py --include-renderer`, before and after, same script both sides:

| | Before | After |
|---|---:|---:|
| every target, native | 542 / 979 | **561 / 979** |
| every target, shimmed | 702 / 979 | **720 / 979** |
| — `Core/.../WWAudio`, native | 0 / 19 | **19 / 19** |
| — `Core/.../WWAudio`, shimmed | 1 / 19 | **19 / 19** |
| — `Core/GameEngineDevice`, native | 6 / 70 | 6 / 70 |

The default (non-renderer) probe is unchanged at 489/737 native and 638/737 shimmed, so the
committed baselines in `docs/porting/ci-baselines/` do not move.

**The probe over-reports this slice, and that is worth recording.** It runs
`clang++ -fsyntax-only`, which never emits vtables, so it never instantiates the *virtual* member
bodies of class templates. The real top-level build does:

```
cmake -S . -B build/native -G Ninja -DRTS_BUILD_ZEROHOUR=ON -DRTS_BUILD_GENERALS=OFF
cmake --build build/native --target z_wwaudio -- -k 0
```

produces **10 of 19** object files with clang-14 (13 with g++-11, which is more permissive about
one of the casts). All remaining failures are one diagnostic:
`Core/Libraries/Source/WWVegas/WWSaveLoad/persistfactory.h:123: cast from pointer to smaller type
'uint32' loses information` — `SimplePersistFactoryClass::Save` writes the object pointer into the
save chunk as a 32-bit id. That is the save/load 64-bit slice (it changes the save-file format), not
this one, so it is left alone; it blocks `AudibleSound`, `FilteredSound`, `LogicalListener`,
`LogicalSound`, `Sound3D`, `SoundPseudo3D` and their dependents.

Backend, built by the real top-level build and checked with `nm`: **101 declared, 101 defined, 0
missing**. `audio-surface.md` claimed 100/100 from the standalone harness; corrected there.

## 6. CI

The `openal-backend` job no longer builds a harness. It configures the top-level project off
Windows, builds `core_openalaudiodevice`, checks declared-vs-defined `AIL_*` symbols, runs
`audio-surface-scan.py --check`, and then builds `z_wwaudio` with `-k 0` and requires at least
10 of 19 objects — a ratchet, not a pass/fail on the save/load blocker.
`scripts/ci/openal-standalone/` is deleted. jammy's CMake 3.22 is too old for the root
`CMakeLists.txt` (needs 3.25), so the job pip-installs CMake 4.1.2.

## 6a. The native build links it, and every `AIL_*` the engine references resolves

`scripts/native-build.py` — the harness that compiles the engine's libraries with clang and runs a
real linker over the archives — did not build this backend, so it reported the whole Miles surface as
unresolved. Measured on `a6ef778ed`, shimmed:

| Undefined `AIL_*` symbols | Before | After |
|---|---:|---:|
| levels 1-3 (`GameEngineDevice`, so `MilesAudioManager.cpp`) | 60 | **0** |
| levels 1-4 (adds `WWAudio`'s 19 units) | 89 | **0** |
| unresolved symbols, all causes, levels 1-4 | 412 | **323** |

All 89 were defined by the backend already; nothing was implemented or stubbed for this, and the
difference in the total is exactly 89. The category was the same artefact level 4 removed for the
renderer: *the build excluded the layer that defines them*. The backend is built as a **support**
archive, like lzhl — it is a dependency of the measured libraries rather than one of them, so the
objects/translation-unit denominators still match the probe's — and OpenAL itself is linked from the
system library, with `scripts/ci/fetch-probe-deps.sh` provisioning `<AL/al.h>` from openal-soft at
the tag `cmake/openal.cmake` pins so the backend also compiles on a box without `libopenal-dev`.

`scripts/ci/check-audio-backend-linked.py` gates both halves in the two `native-build` jobs: that the
backend archive is in the link (its absence would put the count back up while looking like a ratchet
holding), and that no `AIL_*` is unresolved. That second assertion is the one the existing gates
cannot make — `check-openal-symbols.py` compares declared against defined *inside* the backend, and
`audio-surface-scan.py --check` compares demanded against declared *by source scan*; neither can see
a symbol the engine references that `mss.h` never declares. Only a link can, and now one does.

## 7. What the next slice in this area has to solve

1. **`WWSaveLoad` pointer-width** (`persistfactory.h:123`, `pointerremap.h`): the remaining 9
   WWAudio TUs, and far more elsewhere. Save-file compatibility is the real question, not the cast.
2. ~~**`GameEngineDevice` off Windows**, so `MilesAudioManager.cpp` — the largest consumer, 100
   references — is compiled against the backend at all.~~ Done: it is one of `Core/GameEngineDevice`'s
   69 objects in the shimmed native build, and its `AIL_*` references resolve against the backend
   there (section 6a). Whether it *runs* is untouched by that.
3. **MP2/MP3 decoding.** `AIL_open_stream` handles WAV; Zero Hour's music is compressed. Streams of
   unsupported formats currently open, report zero length and play silence. FFmpeg is already an
   optional dependency for video and is the obvious route.
4. **EFX**, to turn the 2 recorded filter entry points into audible reverb/mono-delay.
5. **The Bink handoff.** `AIL_get_DirectSound_info` returns nulls by design: Bink asks Miles for the
   raw `IDirectSound`/`IDirectSoundBuffer` it should mix into. There is no portable equivalent —
   whatever replaces Bink natively has to own its own output path (its own OpenAL source fed by the
   video decoder, or a mixer both sides submit to). Supplying a fake `AILLPDIRECTSOUND` would be
   dishonest, so the backend does not.
6. **Hearing it.** Everything above is compile-time. Playing one sample requires a linkable game
   binary and retail `.big` archives.

# The optimised native build

Every macOS game binary built by `scripts/native-build.py` before this change was compiled at `-O0`:
`configure()` passed `-DCMAKE_BUILD_TYPE=Debug`, which for clang adds `-g` and no `-O`. Retail
Windows is optimised. This slice makes the release configuration optimised, keeps the simulation's
replays in sync, and records what that was measured to buy.

Evidence categories are kept apart: **MEASURED** (with the method), **INFERRED** (from source or
from another measurement, not run), **UNMEASURED**.

Background, measured in stage 2 (`docs/porting/late-game-frame-cost.md` §10 on the branch
`research/late-game-frame-cost`): `-O2 -fno-strict-aliasing` desyncs both late-game recordings
(`CRC Mismatch` at frames 700 and 2,600), because Apple clang's default `-fno-math-errno` lets the
backend fuse `sinf(x)` and `cosf(x)` in `Locomotor.cpp` into `__sincosf_stret`, whose results differ
in the last bits; adding `-fmath-errno` plays both to the end in sync.

## 1. Pre-registered rule (written before this slice built or measured anything)

Recorded verbatim as given, then applied mechanically; not tuned after the data.

> Open a PR only if ALL hold for a binary built by the CHANGED `native-build.py` (not hand-set env flags):
> 1. `macos-binary-opt-level.py` reports it optimised; `lipo -archs` arm64; not translated.
> 2. Headless replay of both recordings plays to the last frame with no `CRC Mismatch`, 2 runs each.
> 3. Headless wall time for game minutes 10→end ≤ 0.6× A's (A = the existing `-O0` binary's numbers in `~/devin-work/late-game/summary-headless.txt`, or re-measured) on both recordings.
> 4. Rendered replay of `heavy-before-2`, fullscreen 1728x1117: late-game (≥ min 12) median frame time ≥ 8 ms lower than A's (A: 53.3 ms in stage 2), and p95 not worse.
> 5. Every repo gate the skills list for a build-system change passes on the Mac; any CI baseline that legitimately changes (e.g. native-build baselines, probe numbers, `check-doc-figures`) is regenerated by the documented method — or, if the skill says it must be regenerated on Linux clang-14, run that in Docker (an Ubuntu image with the CI packages exists: `zh-native-build`, `zh-native-build-amd64`; CI runs amd64) — and the debug-configuration CI job (`Native build, debug configuration + assert negative control`) still builds its debug config.
>
> If any fails: no PR; commit the doc with the numbers and say why.

**Operational definitions, fixed with the rule** (the same as stage 2's §10.1, so A's numbers
transfer):

- *Last frame.* `heavy-before-2` 32,098 and `heavy-aftersync-1` 28,148, the frames every in-sync A
  and B2 run reached in stage 2.
- *Headless wall time, minutes 10→end.* From `ZH_LOGIC_FRAME_LOG`: end of the last logic frame minus
  `start_ms` of logic frame 18,000; the mean of the two runs per recording, divided by the mean of
  A's two runs in `summary-headless.txt` (A: 515.45 s on `before-2`, 555.15 s on `aftersync-1`; 0.6× is 309.3 s and 333.1 s).
- *Rendered late-game frame time.* From `ZH_ENGINE_FRAME_LOG`: successive passes' `start_ms`
  differences over passes with `logic_frame` ≥ 21,600 up to the last frame; one run; median and p95.
  "p95 not worse" means ≤ A's 144.0 ms.
- *The measured binary.* The timing hooks (`ZH_LOGIC_FRAME_LOG`, `ZH_ENGINE_FRAME_LOG`) are not on
  `main`, and this slice changes no engine code. The measured binary is this branch with stage 2's
  two hook commits (`0c964298b`, `aa606e0d8`) applied on top in a scratch checkout, built by this
  branch's `native-build.py` with no flag set in the environment. A carried the same hooks, so the
  pair differs only in how it was compiled. The hooks are dormant unless their variable is set.
